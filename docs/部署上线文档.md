## 二、做了什么（部署过程记录）

### 1. 摸清服务器环境
- 确认服务器为 ARM64 架构（DGX Spark）、Ubuntu 24.04、Python 3.12、有 sudo 权限、可出外网。
- 验证 4 个源数据库从服务器均可连通：
  - `192.168.2.182:3306`（MySQL 测试库）✅
  - `dptonlyread.rwlb.rds.aliyuncs.com:3306`（阿里云 RDS 大平台）✅
  - `114.113.151.55:3306`（飞霞系统 MySQL）✅
  - `114.113.151.60:1521`（教务系统 Oracle）✅

### 2. 上传代码
- 将项目上传到 `/home/spark1/dataTrans`（含 `app.py`、`static/`、`config.json`、`mappings.json`、`auto_fill_rules.json`、`.env`、`sync_state.json`）。
- 排除 `.git/`、`__pycache__/`、`*.log`。
- `.env`（含数据库密码与简道云 API Key）原样搬入，**不进 git**。

### 3. 安装 Python 依赖
```bash
python3 -m venv .venv
.venv/bin/pip install fastapi uvicorn pymysql requests pydantic oracledb
```
实际安装版本：`oracledb 26.0.0`、`fastapi 0.141.1`、`uvicorn 0.53.0`、`pymysql 1.2.0` 等（均为 ARM64 可用的 wheel）。

### 4. 处理 Oracle 连接（本次部署的关键难点）

**问题 1：Oracle 服务器版本太老。**
实测连接发现教务系统是 **Oracle 10g（10.2.0.5）**。`oracledb` 的 thin 模式（纯 Python、免客户端）不支持 10g（报 `DPY-3010`），必须用 **thick 模式 + Oracle Instant Client**。

**问题 2：ARM64 架构没有你 Windows 上那个 21c 客户端。**
Oracle 官方对 Linux ARM64 只提供 19c 和 23ai 两种 Instant Client；而 23ai 客户端不支持连接 10g，因此只能选 **Instant Client 19c（19.32）**。

**最终方案：**
1. 从 Oracle 官网下载 `instantclient-basic-linux.arm64-19.32.0.0.0dbru.zip`（87MB，校验 SHA256 通过），解压到 `/opt/oracle/instantclient_19_32`。
2. 安装 `libaio1t64`，并补建软链接 `libaio.so.1 -> libaio.so.1t64`（Ubuntu 24.04 把 `libaio1` 改名了，Oracle 客户端需要旧名字）。
3. 把客户端目录写入 `/etc/ld.so.conf.d/oracle.conf` 并 `ldconfig`。
4. 验证 thick 模式连接成功，能正常查出 schema（BFEC/SHFEC/GZFEC）、表、列、数据。

### 5. 修改配置
- `config.json` 中 `oracle-clazz` 的 `instant_client` 由 Windows 路径改为：
  ```json
  "instant_client": "/opt/oracle/instantclient_19_32"
  ```
- 其余配置（数据源、映射、`.env`）保持与开发机一致，无需改动。

### 6. 注册为 systemd 服务
`/etc/systemd/system/datatrans.service`：
```ini
[Unit]
Description=dataTrans 数据迁移工具
After=network.target

[Service]
Type=simple
User=spark1
Group=spark1
WorkingDirectory=/home/spark1/dataTrans
Environment=LD_LIBRARY_PATH=/opt/oracle/instantclient_19_32
ExecStart=/home/spark1/dataTrans/.venv/bin/python -m uvicorn app:app --host 0.0.0.0 --port 8088
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```
已 `systemctl enable`（开机自启）+ `restart`（启动）。

### 7. 验证
- 首页 `GET /` 返回 200。
- `/api/sources` 返回 4 个数据源。
- `/api/databases`（Oracle schema、MySQL 库）、`/api/tables`、`/api/columns`、`/api/preview`（含 Oracle 数据预览）均正常。
- `/api/jdy/fields` 正常，说明简道云 API Key 有效。
- `/api/sync/status` 显示 7 套映射的同步状态（含 3 套 Oracle 映射）已正确加载。
- 从内网本机访问 `http://192.168.6.138:8088` 返回 HTTP 200。

## 三、使用说明

### 1. 访问工具
公司内网浏览器打开：

```
http://192.168.6.138:8088
```

界面与开发机一致：左侧选数据源 → 库 → 表 → 勾选字段 → 右侧映射到简道云字段 → 预览 → 确认传输；也支持「即时同步」和「自动同步」。详细操作见 `README.md`。

### 2. 数据源
已配置 4 个数据源，无需再配：
- `182测试数据库`（MySQL，192.168.2.182）
- `大平台后台系统`（MySQL 阿里云 RDS）
- `教务系统`（Oracle，10g，三个 schema：BFEC / SHFEC / GZFEC）
- `飞霞系统`（MySQL，114.113.151.55）

> 密码统一存在服务器 `/home/spark1/dataTrans/.env` 中，前端看不到、也不会下发。

### 3. 自动同步（轮巡）
- 轮巡间隔 300 秒（5 分钟），**仅在 08:00 ~ 20:00 运行**，其余时间休眠。
- 默认关闭，需在页面点「单源同步 / 全部同步」按钮开启；重启服务后需重新开启（内存态）。

## 四、日常运维命令

```bash
# 查看服务状态
sudo systemctl status datatrans

# 重启 / 停止 / 启动
sudo systemctl restart datatrans
sudo systemctl stop datatrans
sudo systemctl start datatrans

# 实时看日志
sudo journalctl -u datatrans -f

# 应用自身日志
tail -f /home/spark1/dataTrans/uvicorn.log     # Web 访问日志

```

> 若修改了 `config.json` / `.env` / `mappings.json`，需 `sudo systemctl restart datatrans` 生效。

## 五、重要注意事项 ⚠️

1. **无登录鉴权**：本工具目前没有账号密码，能访问 `192.168.6.138:8088` 的人即可操作（增删数据源、触发传输、写简道云）。服务器是内网私有 IP（192.168.x.x），**只对内网开放，请勿配置公网端口映射**。如未来需要校外访问，务必先加登录鉴权或走公司 VPN。
2. **密码明文**：`.env` 存有数据库密码与简道云 API Key，注意文件权限，不要提交到 git。
3. **Oracle 依赖**：教务系统是 Oracle 10g，依赖 `/opt/oracle/instantclient_19_32` 和 `libaio`，**不要删除**该目录。
4. **同步状态**：`sync_state.json` 记录每套映射的已同步进度（max_id/rows/hash）。如果误删，下次同步会触发「重新对账」，把数据全量重写简道云，注意谨慎操作（页面上的「重置同步」按钮同理）。
5. **时间筛选**：自动同步默认只同步 `2026` 年及之后的数据（`app.py` 中 `SYNC_TIME_FROM`）。

## 六、若需在其他服务器重装（要点备忘）

1. 先确认服务器 CPU 架构：`uname -m`。
2. 若是 **x86_64**：可用 Instant Client 21c（与你 Windows 一致，thick 模式）；若是 **ARM64**：只能装 19c（本方案）。
3. Ubuntu 24.04 下 libaio 包名为 `libaio1t64`，并需补 `libaio.so.1` 软链接。
4. Oracle 10g 不支持 oracledb thin 模式，必须 thick + Instant Client。
