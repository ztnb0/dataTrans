# 数据源功能 — 自定义添加数据源

> 本文档描述「前端左侧数据板块新增数据源导入界面」的实现逻辑。
> 目标：用户可以**自行添加数据源**（填写连接信息），而不只是从后台预设的数据源中挑选。
> 关联分支：`feature/自定义添加数据源`

---

## 一、背景与目标

### 现状
- 数据源连接信息写死在 `config.json` 的 `sources` 数组中；密码写在 `.env`，按 `DB_<ID>_PASSWORD` 命名。
- 后端启动时 `load_config()` 一次性读入内存字典 `SOURCES`（`app.py`）。
- 前端左栏「数据源」是一个**只读的搜索下拉框**（`static/index.html` 的 `loadSources` / `renderSourceDrop`），只能从现有数据源里选择，没有添加入口。
- 后端只提供只读的 `GET /api/sources`。

### 目标
1. 左栏数据源区域新增「+ 添加数据源」按钮，点开后以**模态框**表单填写连接信息。
2. 提供「测试连接」按钮，保存前先验证能否连上。
3. 保存后新增数据源**持久化**：连接信息写入 `config.json`，密码写入 `.env`，重启后仍存在。
4. 支持**删除**用户自己新增的数据源（内置数据源不可删）。

### 原则
- **不改动任何已实现功能**：现有传输、预览、映射、时间筛选、Oracle 合并等逻辑一律不动。
- 密码绝不出现在任何 GET 响应中。

---

## 二、总体设计

| 层 | 改动 |
|---|---|
| 后端 `app.py` | 新增 `SourceRequest` 模型；新增持久化函数；新增 3 个接口（test / add / delete） |
| 前端 `static/index.html` | 数据源区域加「+ 添加数据源」按钮与模态框；下拉选项加删除 `×`；新增 JS 函数与 CSS |
| 配置 | 用户新增的数据源带 `"user_added": true` 标记，便于区分内置/用户数据源 |

---

## 三、后端实现逻辑（`app.py`）

### 3.1 数据源标记
- 用户新增的数据源在持久化时追加字段 `"user_added": true`。
- 内置数据源（`dpt-182` / `dpt-aliyun` / `oracle-clazz`）**保持原样，不添加任何字段**，从而不被删除逻辑命中。

### 3.2 新增 Pydantic 模型（放在模型区，`TransferRequest` 附近）
```python
class SourceRequest(BaseModel):
    type: str = 'mysql'            # mysql / oracle
    name: str
    host: str
    port: int
    user: str
    password: str = ''
    charset: str = 'utf8mb4'       # mysql 用
    service: str = ''              # oracle 用
    schemas: List[str] = []        # oracle 多 schema
    instant_client: str = ''       # oracle thick 模式路径
```

### 3.3 持久化函数（放在 `load_config` 附近）
1. `save_config()`：
   - 把内存 `SOURCES` 字典值列表按原顺序写回 `config.json`，结构为 `{"sources": [...]}`。
   - 使用 `ensure_ascii=False, indent=2`，与现有 config.json 风格一致。
2. `save_env_password(source_id, password)`：
   - 计算 key = `password_env_key(source_id)`。
   - 读取 `.env` 全部行：若已存在 `KEY=` 开头的行则替换其值；否则在文件末尾追加一行 `KEY=value`。
   - 保留其余注释与配置行不动。
   - 写完后同步 `os.environ[key] = value`，使本次运行立即生效。
3. `gen_source_id(name)`：
   - 由 name 生成一个与现有 id 不冲突的唯一 id，形如 `user-<slug>-<短时间戳>`。
   - 若生成结果已存在于 `SOURCES`，则追加数字后缀直到唯一。

### 3.4 新增接口（放在 `/api/sources` 附近）

#### (1) `POST /api/sources/test` — 测试连接（不落盘）
- 接收 `SourceRequest`。
- 用请求体拼出一个临时 `source` dict（含 `password`），复用连接逻辑尝试建立连接：
  - mysql 走 `pymysql.connect`（host/port/user/password/charset）。
  - oracle 走 `get_oracle_conn` 的厚客户端初始化 + DSN 逻辑。
- 连接成功返回 `{'ok': True, 'message': '连接成功'}`；失败返回 `{'ok': False, 'message': <错误信息>}`（HTTP 200，由前端读 `ok`）。
- 不写 `config.json`、不写 `.env`、不修改 `SOURCES`。

#### (2) `POST /api/sources` — 新增数据源
- 校验：`type` 必须是 `mysql`/`oracle`；`name`/`host`/`user` 非空；`port` 为整数（mysql 默认 3306、oracle 默认 1521）。
- 生成唯一 id：`source_id = gen_source_id(name)`。
- 组装 `source` dict：把 `SourceRequest` 字段落到 dict（去掉空的 oracle 专属字段），并加 `"user_added": True`。
- 写入 `SOURCES[source_id] = source`。
- 调 `save_config()`；若 `password` 非空则调 `save_env_password(source_id, password)`。
- 返回 `{'source': {id, name, type, schemas, user_added}}`（**不含密码**）。

#### (3) `DELETE /api/sources/{source_id}` — 删除数据源
- 若 `source_id` 不在 `SOURCES` → 404。
- 若该数据源**没有** `user_added` 标记 → 拒绝（400，「内置数据源不允许删除」）。
- 从 `SOURCES` 删除 → `save_config()`。
- 从 `.env` 删除对应密码行（若存在）：新增辅助函数 `delete_env_password(source_id)`，逐行过滤掉 `KEY=` 开头的行；并 `os.environ.pop(key, None)`。
- 返回 `{'ok': True}`。

### 3.5 修改现有 `GET /api/sources`
- 在返回每个源时**追加** `user_added` 字段（`bool(s.get('user_added'))`），供前端判断哪些可删。
- 其余字段不变（id/name/type/schemas），不新增密码。

## 四、前端实现逻辑（`static/index.html`）

### 4.1 左栏「数据源」区域
- 在「数据源」label 行新增一个小按钮 `+ 添加数据源`（`onclick="openAddSource()"`）。

### 4.2 模态框结构（`<body>` 末尾新增一个 `div`，默认 `display:none`）
- 遮罩层 + 居中弹窗，标题「添加数据源」。
- 表单字段：
  - `类型`（select：mysql / oracle；切换时显示/隐藏 oracle 专属字段）
  - `名称`、`主机`、`端口`（数字）、`用户名`、`密码`（password）、`字符集`（默认 gbk，仅 mysql 显示）
  - Oracle 专属：`服务名`、`Schema 列表`（逗号分隔，可留空）、`Instant Client 路径`（可留空）
- 底部按钮：`测试连接`（灰）、`保存`（绿）、`取消`（灰）。
- 一个提示区（显示测试连接结果 / 错误信息）。

### 4.3 JS 逻辑
1. `openAddSource()`：显示模态框，重置表单默认值（mysql、端口 3306、字符集 gbk）。
2. `toggleSourceForm()`：根据「类型」切换 oracle 专属字段的显示，并自动把端口默认值改为 3306 或 1521。
3. `testSource()`：收集表单 → `POST /api/sources/test` → 在提示区显示成功/失败，按钮禁用期间防重复点击。
4. `saveSource()`：收集表单 → `POST /api/sources` → 成功后关模态框、`refreshSources()`，并可选中新源。
5. `refreshSources()`：重新 `fetch('/api/sources')` 更新 `sourceList`，重渲染下拉。
6. `deleteSource(id, event)`：
   - 仅对 `user_added` 为 true 的源显示删除 `×`。
   - 点击时 `event.stopPropagation()`（避免触发选中），`confirm` 确认后 `DELETE /api/sources/{id}`，成功后 `refreshSources()`。
   - 若删除的是当前选中源，则清空左栏 db/表/字段。

### 4.4 下拉选项渲染（改造 `renderSourceDrop`）
- 每个选项后追加删除按钮 `×`，仅当 `s.user_added` 为 true 时渲染。
- 删除按钮 `onclick` 内联调用 `deleteSource` 并 `stopPropagation`。

### 4.5 CSS
- 新增 `.modal-mask`（遮罩，半透明，覆盖全屏，`z-index` 高）、`.modal`（居中白底弹窗）、`.modal h2`、`.modal .row`、`.modal label/input/select`、`.modal .actions` 按钮组、`.del`（下拉里的删除小按钮）等，风格与现有 `.panel`/`.btn` 一致。

## 五、安全与边界
- 密码不出现在 `GET /api/sources`；仅在新增时接收一次并写入 `.env`。
- 测试连接接口只读，不产生持久化副作用。
- 必填校验：`name`/`host`/`user` 非空，`type` 只允许 mysql/oracle。
- 删除接口只允许 `user_added` 数据源；内置数据源不可删。
- `.env` 写入只增改目标密码行，保留其它内容。

---

## 六、测试与验证

1. 启动：`python -m uvicorn app:app --host 127.0.0.1 --port 8088`。
2. 左栏点「+ 添加数据源」→ 弹出模态框。
3. 填一个 MySQL 数据源（用 182 测试库信息）→ 点「测试连接」→ 显示「连接成功」。
4. 点「保存」→ 模态框关闭 → 下拉列表出现新数据源 → 能浏览库/表/字段。
5. 重启服务后新数据源仍在（验证 config.json 与 .env 已更新）。
6. 点新数据源的 `×` → 确认 → 从列表消失；重启后仍不存在。
7. 内置数据源（如 dpt-182）下拉里**不显示**删除 `×`，且直接调用删除接口返回 400。
8. 用错误密码测试连接 → 显示失败信息。
9. 回归：原有三级浏览、字段映射、预览、传输不受影响。

- 传输链路：`/api/transfer/preview`、`/api/transfer`、`_read_rows`、`_count_rows`、`normalize_value` 等一律不动。
- 浏览链路：`/api/databases`、`/api/tables`、`/api/columns`、`/api/preview` 逻辑不动。
- 简道云相关：`/api/jdy/*` 不动。
