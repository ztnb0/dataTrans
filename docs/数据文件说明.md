# 数据文件说明

> 本文档解释 `app.py` 里四个路径常量对应的本地文件——`mappings.json`、`auto_fill_rules.json`、`sync_state.json`、`sync.log`——各存放什么数据、字段含义与功能。

代码中的路径定义：

```python
BASE_DIR = os.path.dirname(os.path.abspath(__file__))   # 项目根目录
MAPPINGS_PATH        = os.path.join(BASE_DIR, 'mappings.json')
AUTO_FILL_RULES_PATH = os.path.join(BASE_DIR, 'auto_fill_rules.json')
SYNC_STATE_PATH      = os.path.join(BASE_DIR, 'sync_state.json')
SYNC_LOG_PATH        = os.path.join(BASE_DIR, 'sync.log')
```

四个文件都在项目根目录，作用各不同，见下文。

---

## 一、`mappings.json` —— 字段映射配置

### 定位
存放「源表字段 → 简道云字段」的**映射关系**，是即时同步的核心配置。前端在「字段映射」面板点「保存映射」按钮写入，可有多套（当前 6 套）。

### 数据结构

```json
[
  {
    "id": "dpt-aliyun-groupbatch",
    "source": "dpt-aliyun",
    "database": "dpt_e-commerce",
    "table": "groupbatch",
    "source_fields": ["id", "batchName", "createDate", "classnumber"],
    "target_fields": ["_widget_1789030761638", "_widget_1788918827861", "_widget_1788918827862", "_widget_1788918827860"],
    "platform_value": "大平台后台系统",
    "data_type_value": "大平台期次",
    "transforms": ["", "", "", ""],
    "enabled": true
  }
]
```

### 字段含义

| 字段 | 类型 | 说明 / 取值 |
|---|---|---|
| `id` | string | 映射唯一标识。MySQL 用 `源-表`，Oracle 用 `源-schema-表`（避免三 schema 同名 CLAZZ 撞 id）。例：`dpt-aliyun-groupbatch`、`oracle-clazz-BFEC-CLAZZ` |
| `source` | string | 数据源 id，对应 `config.json` 里某数据源的 `id`。例：`dpt-aliyun`、`oracle-clazz`、`user-src-1789010399` |
| `database` | string | 源库名（Oracle 为 schema 名）。例：`dpt_e-commerce`、`BFEC`、`mexam3` |
| `table` | string | 源表名。例：`groupbatch`、`CLAZZ`、`db_plan_positon` |
| `source_fields` | string[] | 源表字段名列表，**第一项通常是主键**。例：`["id","batchName","createDate","classnumber"]` |
| `target_fields` | string[] | 简道云字段 key 列表，与 `source_fields` **一一对应**。例：`["_widget_1789030761638", ...]` |
| `platform_value` | string | 写入简道云「平台」字段的固定值。例：`大平台后台系统`、`教务系统`、`飞霞系统` |
| `data_type_value` | string | 写入简道云「数据类型」字段的固定值，**每张表全局唯一**（参与定位匹配）。例：`大平台期次`、`教务北京` |
| `transforms` | string[] | 每个源字段的转换规则，与 `source_fields` 等长；`""`=无转换，`batch_number`=提取批次号，`city_name`=市名+考场（仅飞霞用） |
| `enabled` | bool | 是否启用该映射。`false` 时轮巡跳过这套映射 |

### `target_fields` 对应的简道云字段 key

| 简道云 key | 含义 |
|---|---|
| `_widget_1789030761638` | id（存源表主键，定位匹配键之一） |
| `_widget_1789030761637` | 数据类型（匹配键之一，存 `data_type_value`） |
| `_widget_1788918827859` | 平台（存 `platform_value`） |
| `_widget_1788918827860` | 项目编号（业务字段） |
| `_widget_1788918827861` | 项目名称（业务字段） |
| `_widget_1788918827862` | 平台数据创建时间（业务字段） |

### 功能
- 前端「保存映射」写入，重启后仍在（持久化）；
- 轮巡按这套映射读源表字段、套转换规则、组装简道云记录写入；
- 简道云里定位数据靠「源表主键（存 id 字段）+ `data_type_value`（数据类型）」组合。

## 二、`auto_fill_rules.json` —— 平台/数据类型自动填充规则

### 定位
存放前端「规则管理」面板维护的**自动填充规则**：选了某个数据源 + 库/表后，自动填「平台」和「数据类型」两个固定值，省得手填。

### 数据结构

```json
[
  {
    "source_name": "大平台后台系统",
    "platform": "大平台后台系统",
    "data_types": [
      { "match": "dpt_product",    "value": "大平台班级" },
      { "match": "dpt_e-commerce", "value": "大平台期次" }
    ]
  },
  {
    "source_name": "教务系统",
    "platform": "教务系统",
    "data_types": [
      { "match": "BFEC",   "value": "教务北京" },
      { "match": "SHFEC",  "value": "教务上海" },
      { "match": "GZFEC",  "value": "教务广州" }
    ]
  }
]
```

### 字段含义

| 字段 | 类型 | 说明 / 取值 |
|---|---|---|
| `source_name` | string | 数据源名，对应 `config.json` 里某数据源的 `name`。例：`大平台后台系统` |
| `platform` | string | 该数据源下所有表共用的「平台」固定值 |
| `data_types` | array | 数据类型规则数组 |
| `data_types[].match` | string | 匹配条件：库名（MySQL）/ schema 名（Oracle）/ 表名 |
| `data_types[].value` | string | 匹配命中时填的「数据类型」值 |

### 功能
- 前端 `applyAutoDefaults()` 在选库/表时，按 `source_name` + `match` 命中后自动填「平台」「数据类型」；
- 保存映射时这两个值被写进 `mappings.json` 的 `platform_value` / `data_type_value`。

## 三、`sync_state.json` —— 轮巡同步状态「账本」

### 定位
轮巡的**运行时状态**，由后台轮巡**自动维护**（首次对账时生成，之后每轮更新），**不是手工编辑的配置**。已加入 `.gitignore`（不进版本库）。

### 数据结构

```json
{
  "<mapping_id>": {
    "max_id": 12715,
    "last_sync_time": "2026-09-16 10:30:00",
    "rows": {
      "3387": { "data_id": "6aa39876a338309858a042c2", "hash": "abc123" }
    },
    "reconciled": 990,
    "created": 10
  }
}
```

### 字段含义

| 字段 | 类型 | 说明 / 取值 |
|---|---|---|
| 顶层 key | string | 映射 id，与 `mappings.json` 里 `id` 对应 |
| `max_id` | int | 上次同步到的最大主键。下次只查 `主键 > max_id` 即判定为「新增」 |
| `last_sync_time` | string | 上次同步完成时间（格式 `YYYY-MM-DD HH:MM:SS`），状态记录用 |
| `rows` | object | `源表主键 → { data_id, hash }` 的对应关系表 |
| `rows[主键].data_id` | string | 简道云该条数据的内部唯一编号，**update 时定位用** |
| `rows[主键].hash` | string | 源表该行映射字段值算出的 md5，**修改检测用**（下次对比是否变化） |
| `reconciled` | int | 首次对账时「接管」的条数（源表有、简道云也有的行数），对账后保留 |
| `created` | int | 首次对账时「补新增」的条数（源表有、简道云没有的行数），对账后保留 |

### 功能（账本三类账）
1. **记到哪儿了**（`max_id`）：判断哪些行是新增，避免全表扫；
2. **记对应关系**（`rows[主键].data_id`）：知道更新简道云里哪一条；
3. **记旧值**（`rows[主键].hash`）：和下次源表值对比，判断是否被修改。

## 四、`sync.log` —— 轮巡运行日志

### 定位
后台轮巡的**日志文件**，由 `log_sync()` 追加写入，用于查看轮巡结果和排查问题。已加入 `.gitignore`（不进版本库）。

### 格式
每行一条，形如：

```
[2026-09-16 10:21:42] 轮巡线程已启动（间隔 300 秒，20:00~08:00 休眠；默认不自动同步，由前端按钮开启）
[2026-09-16 10:30:00] 开始一轮同步，共 6 套映射
[2026-09-16 10:30:02] [dpt-aliyun-groupbatch] 首次运行，开始对账
[2026-09-16 10:30:05] [dpt-aliyun-groupbatch] 对账完成：接管 990 条，新增 10 条，max_id=12715
[2026-09-16 10:30:08] [dpt-aliyun-groupbatch] 完成：新增 0，修改 0
[2026-09-16 10:30:10] 本轮同步结束
[2026-09-16 10:35:00] 本轮无开启自动同步的数据源，跳过
```

### 记录的典型内容

| 类型 | 示例 |
|---|---|
| 轮巡线程启动 | `轮巡线程已启动（间隔 300 秒，20:00~08:00 休眠；默认不自动同步，由前端按钮开启）` |
| 无开启的同步源 | `本轮无开启自动同步的数据源，跳过` |
| 一轮开始/结束 | `开始一轮同步，共 N 套映射` / `本轮同步结束` |
| 首次对账 | `[id] 首次运行，开始对账` / `[id] 对账完成：接管 X 条，新增 Y 条，max_id=…` |
| 每套映射结果 | `[id] 完成：新增 N，修改 M` |
| 错误 | `[id] 同步失败: …` / `[id] batch_create 部分失败…` / `[id] 更新 pk=… 失败: …` |
| 休眠 | `休眠时间段，睡 N 秒至次日 08:00` |

## 五、总览对比

| 文件 | 性质 | 谁写入 | 是否已存在 | git 跟踪 | 功能 |
|---|---|---|---|---|---|
| `mappings.json` | 配置 | 前端「保存映射」 | ✅ 已存在 | ✅ 提交 | 字段映射关系（同步的依据） |
| `auto_fill_rules.json` | 配置 | 前端「规则管理」 | ✅ 已存在 | ✅ 提交 | 平台/数据类型自动填充规则 |
| `sync_state.json` | 状态 | 后台轮巡自动维护 | ❌ 首次对账才生成 | ❌ 忽略 | 同步进度账本（max_id / data_id / hash） |
| `sync.log` | 日志 | 后台轮巡自动追加 | 运行时生成 | ❌ 忽略 | 轮巡结果与报错记录 |

> 简单区分：`mappings.json` 和 `auto_fill_rules.json` 是**人配的输入**（决定"怎么同步"）；`sync_state.json` 和 `sync.log` 是**程序产的输出**（记录"同步到哪了、结果如何"）。
