## 二、后端实现逻辑（`app.py`）

### 1. 数据源管理接口

| 接口 | 说明 |
|---|---|
| `GET /api/sources` | 数据源列表（不含密码） |
| `GET /api/sources/{id}` | 单个数据源完整信息（编辑时预填用，不含密码） |
| `POST /api/sources` | 添加数据源（写 config.json + `.env`，立即生效） |
| `PUT /api/sources/{id}` | 修改数据源（密码留空则保留原密码；新密码更新 `.env`） |
| `DELETE /api/sources/{id}` | 删除数据源（**含内置**，同时清 `.env` 密码行） |
| `POST /api/sources/test` | 测试连接（不落盘） |

- 数据源存 `config.json`（不含密码），密码存 `.env` 的 `DB_<id>_PASSWORD`。
- 添加/修改/删除后同步更新内存 `SOURCES`，**立即生效无需重启**。

### 2. 映射支持转换规则

- `MappingRequest` 新增字段 `transforms: Optional[List[str]] = None`（与 `source_fields` 等长）。
- `build_jdy_record` 对每个源字段套 `apply_transform(value, transform_type)`：
  - `batch_number`：正则 `(\d+)批` 提取批次号；
  - `city_name`：去省份前缀 + 拼「考场」；
  - 返回 `None`（在线考试 / “其他”市名）→ 整行跳过，不写简道云。

### 3. 同步接口支持 Oracle 多 schema

- `NotifyRequest` 新增可选字段 `database`。
- `find_mapping_by_table(table, database)`：先按表名匹配，若传了 `database` 再按它过滤；仍多套则报错。
- `sync_notify` 流程不变：回查 → 组记录（含转换）→ 按「id + 数据类型」查简道云 → 有则 update / 无则 batch_create。

## 三、前端实现逻辑（`static/index.html`）

### 1. 数据源管理

- 「数据源」旁新增「数据源管理」按钮 → 弹窗列出所有数据源，每条「编辑」「删除」。
- 编辑：调 `GET /api/sources/{id}` 预填表单，保存时调 `PUT`；添加时调 `POST`（用 `editingSourceId` 区分）。
- 删除：确认后调 `DELETE`，删完刷新列表。

### 2. 保存映射

- 「② 字段映射」面板新增「保存映射」按钮。
- 点击收集当前界面的 `source / database / table / source_fields / target_fields / transforms / platform_value / data_type_value`，调 `POST /api/mappings` 保存。
- 映射 id 自动生成：MySQL 用「源-表」，Oracle 用「源-schema-表」（避免三 schema 同名 CLAZZ 撞 id）。

### 3. 转换下拉只对「飞霞系统」显示

- `rebuildMapping` 里按 `curSourceName() === '飞霞系统'` 判断，仅飞霞渲染「转换规则」下拉。
- 收集 `transforms` 时对不存在的下拉做空值兜底。

### 4. 平台 / 数据类型自动填充

`applyAutoDefaults()` 在 `loadColumns` 时触发，按数据源名/库/表填充：

| 数据源名 | 平台 | 条件 | 数据类型 |
|---|---|---|---|
| 大平台后台系统 | 大平台后台系统 | 库=dpt_product | 大平台后台班级表单类型---大平台班级 |
| 大平台后台系统 | 大平台后台系统 | 库=dpt_e-commerce | 大平台后台期次表单类型---大平台期次 |
| 教务系统 | 教务系统 | schema=BFEC | 教务系统OracleBFEC---教务北京 |
| 教务系统 | 教务系统 | schema=SHFEC | 教务系统OracleSHFEC---教务上海 |
| 教务系统 | 教务系统 | schema=GZFEC | 教务系统OracleGZFEC---教务广州 |
| 飞霞系统 | 飞霞系统 | 表=db_plan_positon | 飞霞db_plan_positon @mexam3---飞霞 |

### 5. 关掉 Oracle 合并模式

- 去掉 `loadDatabases` 里的 `__ALL__` 合并选项，Oracle 每次只选单个 schema。

## 四、同步接口契约（最终）

```
POST /api/sync/notify
{ "table": "coaching_class", "pk": "123", "database": "" }
```

| 字段 | 说明 |
|---|---|
| `table` | 源表名 |
| `pk` | 该行主键值 |
| `database` | 可选；MySQL 省略，Oracle 必填（schema） |

响应：`{"ok":true,"action":"create"|"update"}` / `{"ok":true,"skipped":"transform_skip"|"row_not_found"}`。

## 六、遗留 / 注意

1. 自动填充的「平台/数据类型」值是**前端硬编码**的规则表；若以后规则变化，需改 `applyAutoDefaults()`。
2. 「飞霞系统」的判断按数据源名 `飞霞系统`（改名后生效）。
3. 数据类型的值同时充当同步匹配键（id + 数据类型），必须每张表唯一，当前规则已保证唯一。
4. 简道云 `delete` 未授权，源表删除仍无法同步。
