# 测试用例：单源同步下「修改 + 新增」数据的行为验证

> 背景：本文档基于「182测试数据库」数据源，验证在**前端开启单源同步**后，在数据库中执行「修改字段值」和「新增一条数据」两条 SQL，后台轮巡会如何反应，以及最终在简道云、`sync.log`、`sync_state.json` 里各自能看到什么。
>
> 相关代码：`app.py`（轮巡与同步逻辑）、`static/index.html`（单源同步按钮）、`docs/sync-lunXun.md`（轮巡方案）。

---

## 一、测试环境

| 项 | 值 |
|---|---|
| 数据源 | 182测试数据库（`dpt-182`） |
| 主机 | `192.168.2.182:3306`（**可写**，MySQL Community Server，`read_only=0`） |
| 账号 | `dpt_dev`（`GRANT ALL PRIVILEGES ON *.*`） |
| 库 / 表 | `dpt_product.coaching_class` |
| 主键 | `id`（`auto_increment`） |
| 映射 id | `dpt-182-coaching_class` |
| 映射字段 | `id → 简道云id`、`class_name → 项目名称`、`class_ctime → 平台数据创建时间`、`class_number → 项目编号` |
| 固定值 | `platform_value = 测试平台`、`data_type_value = 测试班级` |
| 同步时间筛选 | `class_ctime >= 2026`（`SYNC_TIME_FROM='2026'`） |
| 轮巡规则 | 每 5 分钟一轮，仅 08:00 ~ 20:00 执行 |

> ⚠️ 注意：改/增数据必须连到可写的 `192.168.2.182`，不要连 `dptonlyread.rwlb.rds.aliyuncs.com`（那是阿里云只读实例，会报 `[8001] polar slave` 只读错误）。

---

## 二、前置条件

1. 前端已为该表保存映射（`mappings.json` 中存在 `dpt-182-coaching_class`，`enabled=true`）。
2. 当前时间在 **08:00 ~ 20:00** 之间（否则点「单源同步」会被前端拦截，后端也会拒绝）。
3. 当前 `max_id` 约为 `3082`（本轮测试以此为准，实际以数据库最新值为准）。

---

## 三、操作步骤

### 步骤 1：前端开启单源同步

在「③ 平台 & 传输」区点击 **「单源同步」** 按钮（当前选中数据源为 `dpt-182`）。

**后端发生了什么：**

1. 前端校验时间窗口 + 校验当前数据源已保存映射，然后调用 `POST /api/sync/auto/toggle`（`mode=single, source=dpt-182`）。
2. 后端把内存态开关 `AUTO_SYNC['sources']['dpt-182']` 置为 `True`。
3. **立即同步一次**：跑 `dpt-182-coaching_class` 这套映射。
   - 首次运行（`sync_state.json` 里该映射无记录）→ 进入**对账**：
     - 拉取简道云「测试班级」下已有数据，建立「源表主键 ↔ data_id」对应；
     - 源表按 `class_ctime >= 2026` 全量读入；
     - 已在简道云的 → 记 `data_id` + 字段值 hash（接管）；
     - 不在的 → 记为待新增 → `batch_create` 批量写入。
   - `sync.log` 记录：
     ```
     [dpt-182-coaching_class] 首次运行，开始对账
     [dpt-182-coaching_class] 对账完成：接管 X 条，新增 Y 条，max_id=3082
     ```
4. 之后后台轮巡线程**每 5 分钟**自动对该数据源跑一次同步（直到关闭或服务重启）。

> 注意：单源同步开关是**内存态**，重启服务后自动回到关闭。

## 四、用例一：修改字段值（UPDATE）

### 测试 SQL

```sql
UPDATE dpt_product.coaching_class
SET class_name = '测试修改班级名'
WHERE id = 3082;
```

### 预期发生什么

1. 下一轮轮巡（≤5 分钟）执行 `dpt-182-coaching_class` 的同步：
   - **新增检测**：`_query_new_rows` 查 `id > 3082`，本次无新增 → 新增 0。
   - **修改检测**（`_update_by_hash`）：全量读 `class_ctime >= 2026` 的行，对每行用 `id + class_name + class_ctime + class_number` 算新 hash，与 `sync_state.json` 里旧 hash 对比。
     - `id=3082` 的新 hash ≠ 旧 hash → 判定为**被修改**；
     - 用 `data_id` 调简道云 `update` 覆盖该条，更新「项目名称」为 `测试修改班级名`；
     - 更新 `sync_state.json` 中该行的 hash 快照。
2. `sync.log` 出现**逐条明细** + 汇总（逐条明细为本次新增的能力）：

   ```
   [2026-09-16 15:00:00] [dpt-182-coaching_class] 修改 pk=3082：class_name=测试修改班级名, class_ctime=2026-09-15 16:14:38, class_number=WLAFP202600001
   [2026-09-16 15:00:00] [dpt-182-coaching_class] 完成：新增 0，修改 1
   ```

3. 简道云：该 `id` 对应的「测试班级」数据，「项目名称」字段被更新为 `测试修改班级名`。

### 校验点

- `sync.log` 出现 `修改 pk=3082：...` 的逐条明细（说明修改被逐条记录）。
- 简道云表单里该项目名称已更新。

## 五、用例二：新增数据（INSERT）

### 测试 SQL

```sql
INSERT INTO dpt_product.coaching_class (class_name, class_ctime, class_number)
VALUES ('测试新增班级', '2026-09-16 10:00:00', 'TEST202600002');
```

> `id` 自增，会自动生成（新值 > 3082）。`class_ctime` 必须 ≥ 2026 才能被时间筛选命中。

### 预期发生什么

1. 下一轮轮巡执行同步：
   - **新增检测**：`_query_new_rows` 查到 `id > 3082 且 class_ctime >= 2026` 的新行；
     - 先 `jdy_find_by_id` 查重（按「主键 + 数据类型」）→ 不存在；
     - 走 `batch_create` 批量写入简道云；
     - 把返回的 `data_id` 记入 `sync_state.json` 的 `rows`；
     - `max_id` 更新为新主键（如 3083）。
   - **修改检测**：其余行 hash 无变化 → 修改 0。
2. `sync.log` 出现：

   ```
   [2026-09-16 15:05:00] [dpt-182-coaching_class] 完成：新增 1，修改 0
   ```

3. 简道云：多出一条「测试班级」数据，`项目名称=测试新增班级`、`项目编号=TEST202600002`、`平台数据创建时间=2026-09-16 10:00:00`、`平台=测试平台`。

### 校验点

- `sync.log` 出现 `新增 1`。
- 简道云表单里多出对应那条数据。
- `sync_state.json` 中该映射的 `max_id` 变大，`rows` 多一条记录。

## 六、如果两个用例在同一轮轮巡前都执行了

同一轮会同时检测到新增和修改，`sync.log` 汇总为：

```
[dpt-182-coaching_class] 修改 pk=3082：...
[dpt-182-coaching_class] 完成：新增 1，修改 1
```

即「新增」走 `batch_create`，「修改」走单条 `update`，二者互不影响。

---

## 七、注意事项与边界

1. **时间窗口**：只有 08:00 ~ 20:00 轮巡；夜间不检测、不写 `sync.log`（会记 `休眠时间段`）。
2. **时间筛选**：`class_ctime` 必须 ≥ 2026 年，否则新增/修改都不会被同步检测到。
3. **只读实例**：改/增必须连 `192.168.2.182`（可写），连只读实例会报 `polar slave` 错误。
4. **开关内存态**：单源同步开关重启后失效，需重新点击开启。
5. **删除不同步**：简道云 `delete` 接口未授权，源表删行不会同步删除。
6. **逐条明细只记修改**：`sync.log` 里只有「修改」会记逐条明细（`修改 pk=...：字段=值...`），「新增」只记数量，不记逐条。

---

## 八、结论

开启该数据源「单源同步」后，后台进入「立即同步一次 + 每 5 分钟自动轮巡」模式：

- 执行 **UPDATE**（改字段值）→ hash 对比检测到变化 → 单条 `update` 更新简道云 → `sync.log` 记 `修改 pk=3082：...` 逐条明细，汇总 `修改 1`。
- 执行 **INSERT**（新增数据）→ 主键递增检测到新行 → `batch_create` 写入简道云 → `sync.log` 记 `新增 1`，`sync_state.json` 更新 `max_id` 与 `rows`。
